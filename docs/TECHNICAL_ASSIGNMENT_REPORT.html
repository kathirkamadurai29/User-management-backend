3. System Architecture & Data Flow

The platform separates responsibilities cleanly across three architectural tiers:

  • Presentation Tier (Vercel): React 18 SPA bundled with Vite 5, served via edge CDN with push-state routing for both client and Super Admin portals.
  • Application & API Tier (Render): Containerized Python 3.11 FastAPI service handling asynchronous request processing, input validation via Pydantic, CORS policies, and request telemetry logging.
  • Data Plane Tier:
    • Supabase (PostgreSQL 15): Client tenant registration, Super Admin accounts, unique constraints, and bcrypt password/secret hashes.
    • MongoDB Atlas: Polymorphic tenant user documents, dynamic metadata, and high-throughput append-only request telemetry logs.
    • Firebase Storage (Google Cloud Storage): Binary image asset storage for user avatars delivered over Google's global CDN.
    • Google Gemini AI: Operational telemetry synthesis engine analyzing request latency, error distribution, and usage patterns.

4. Multi-Tenant Architecture & Data Isolation

To ensure absolute data isolation across clients:

  1. JWT-Driven Scoping: The client's unique client_id is cryptographically sealed inside the JWT and extracted by the authentication middleware on every request. Client input in query parameters or request bodies is never trusted for tenant identity.
  2. Hard Database Filtering: Every database operation forcibly appends {"client_id": tenant["client_id"], "is_deleted": False} to the query selector.
  3. Zero-Knowledge 404 Rejection: When Tenant B attempts to read or mutate a user belonging to Tenant A, the backend responds with HTTP 404 Not Found (rather than 403 Forbidden). This mathematical guarantee prevents cross-tenant enumeration attacks.

5. Dual-Track Authentication & API Credential Vault

The architecture enforces a strict boundary between human interactive sessions and programmatic machine access:

  • Track 1: Dashboard Interactive Sessions: Tenants register with a username and password. Upon login, they receive a Session JWT (type: "session") allowing them to interact with the dashboard. No API credentials exist at signup.
  • Track 2: Programmatic API Consumer Credentials: Inside the dashboard, the tenant can click "Generate API Credentials". The server generates a unique client_id and high-entropy client_secret. The raw secret is returned to the user exactly once in a dismissible modal and salted/hashed using bcrypt (12 rounds) in Supabase. Programmatic consumers exchange these credentials via POST /api/v1/auth/token for an API JWT (type: "api").

7. Firebase Storage & Google Cloud Platform Integration

TenantCore integrates Firebase Storage (built natively on Google Cloud Storage) for user profile picture management:

  • Upload Flow: The client sends a multipart file upload to POST /api/v1/users/upload-avatar. The backend verifies file extension and MIME type, streams the buffer directly into the Firebase Cloud Storage bucket via the Firebase Admin SDK, and stores the resulting public HTTPS URL in MongoDB.
  • Architectural Benefit: Prevents database collection bloat caused by binary BLOBs, offloads bandwidth to Google's worldwide CDN, and accelerates user directory retrieval speeds.
  • GCP Alignment: Fulfills the Google Cloud assignment bonus requirement using enterprise GCP storage infrastructure.

8. Dockerization & Multi-Platform Cloud Deployment

  • Frontend Dockerization: Multi-stage Alpine Dockerfile. Stage 1 compiles the React Vite bundle; Stage 2 injects the static assets into Nginx 1.25 Alpine with client-side SPA routing rules.
  • Backend Dockerization: Python 3.11 Slim container configured with dependency caching, non-root user execution, and an automated healthcheck probe against /health.
  • Local Orchestration: Complete stack runs locally with a single command: docker compose up --build.
  • Multi-Cloud Deployment:
    • Platform 1 (Vercel): Edge CDN hosting with zero-config SSL and pushstate rewrites.
    • Platform 2 (Render): Managed container runtime with continuous integration connected directly to GitHub.
